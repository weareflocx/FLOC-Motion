# FLOC Motion

A local, internal parametric video studio. Inspired by modern parametric motion editors and public carousel examples. The WebGL layouts, shaders, example posters and editor are original implementations. Official FLOC identifiers are downloaded from the user-supplied brand file.

## FLOC brand

Source: [FLOC Brand System](https://www.figma.com/design/61GRiVYnWbglilWGDN7fUq/FLOC-Brand?node-id=3608-3624). Verified sections: palette `3608:4796`, support gray `3608:4847`, identifiers `3608:4253`.

- Black background, white typography and monochrome demo artwork. Neutral UI surfaces are functional contrast, not additional brand colors.
- Pure RGB (`#FF0000`, `#00FF00`, `#0000FF`) is reserved for meaningful accents. No sage/lime palette, colored panels or RGB gradients by default.
- The header uses the original white wordmark export (`3617:3965`). The composition uses the original white symbol SVG (`3617:4010`), without recoloring or redrawing.
- `src/brand.js` is the shared palette/asset source; the agent catalog exposes it. Uploaded carousel images remain user-controlled and are not recolored automatically.
- Geist remains the work/UI font. The abstract sample posters are original placeholders, not official FLOC graphic-system assets.

## Run

Requires Node.js 24+ (`nvm use` picks it up from `.nvmrc`) and FFmpeg/FFprobe on PATH. Rendering uses installed Google Chrome on macOS when present. Set `HYPERFRAMES_BROWSER_PATH` to select a different working Chromium binary.

Server-local and legacy shared-worker exports store renderer output in `render.log` and result or failure metadata in `job.json`; those modes may retain `video.mp4` (server-local exports also `video.mov` or `frames.zip`) and expose an authenticated browser download. Personal renderers store only status and saved-path metadata on the editor server.
Source video frame format is automatic: the engine keeps PNG for transparency and uses JPEG for opaque footage, independently of the final MP4 quality setting.
Carousel video frames are prepared once with FFmpeg at the project frame rate. Export textures read the prepared images, including alpha-preserving PNGs, instead of seeking browser video decoders. Preview playback still uses the original media. Paused carousel previews request metadata and the first frame instead of eagerly buffering every video; playback and scrubbing fetch further frames as needed.
Export offers **MP4 · H.264** (default, AAC 320 kbps soundtrack), **MOV · ProRes 4444** (alpha plane, 16-bit PCM soundtrack) and **PNG sequence (.zip)** (8-bit `frames/frame_000001.png`… frames, plus `audio.wav` when the project has music; an uncompressed ZIP with ZIP64 offsets past 4 GB). For MOV and PNG, **Transparent background** leaves out background layers and keeps the page transparent; otherwise empty areas are white, as in MP4. Every result is verified before delivery: H.264/yuv420p or ProRes 4444 with an alpha pixel format, dimensions, frame rate, frame count and soundtrack codec; for PNG archives, every frame's name, size and PNG header are read from the ZIP. The legacy Mac render worker accepts MP4 only and rejects other formats before queuing.
Frame capture uses several HyperFrames Chrome workers (about 256 MB each): min(4, CPU cores − 1), or one on machines with 8 GB of RAM or less. Set `FLOC_RENDER_WORKERS` (1–16) to override. Each frame depends only on its supplied time, so worker count does not change the pixels.

Prepared export folders include `render-input.json`, local assets and the compiled scene. A separate host with the same application version, Chromium and FFmpeg can render a trusted folder with `node scripts/render-prepared.mjs <composition-folder>`. The command verifies the result in the requested format and writes `render-result.json`. The Mac render worker below connects the shared editor's export button to a trusted Mac.

```sh
npm ci
npm run dev
```

Open **http://127.0.0.1:4317**. By default, the server binds only to the loopback interface. Public hosting requires the explicit configuration below; accounts share the composition library, with independent saves and no simultaneous editing.

Press **Space** to play or pause the preview, and **Delete/Backspace** to remove the selected unlocked layer. These shortcuts pause while editing fields, using dialogs or manipulating the canvas. Space also works with a layer selection or playback button focused; other buttons retain native activation. Delete on a focused choreography diamond removes that state. Hold-to-repeat does not toggle playback or delete additional layers. Layer deletion supports Undo.

```sh
npm test
npm run build
npm start
```

Tests run serially across files so browser pixel suites do not compete for GPU resources; each visual harness controls its own rendering lanes.

The bundlers use official WebAssembly builds to avoid native esbuild/Rollup binary loading issues. Dependencies are pinned in `package-lock.json`.

## Public hosting (explicit opt-in)

After building, production startup does not load Vite. Set `FLOC_PUBLIC_ORIGIN` to the exact HTTP(S) origin to bind to `0.0.0.0` and permit that host. Multiple origins can be separated by commas; the first is used for generated invitation links. HTTPS mutation checks use the configured origin matching the request host behind the proxy. Without it, production remains loopback-only.

```sh
NODE_ENV=production PORT=8080 FLOC_PUBLIC_ORIGIN=https://floc-motion.fly.dev npm start
```

Access requires an invited account in both local and public modes. Before the first startup, run `npm run invite -- you@example.com` with the same `FLOC_DATA_DIR`, `PORT` and `FLOC_PUBLIC_ORIGIN` as the server. Open the resulting single-use link, enter that email address and choose a password of 12–128 characters. The link expires after 48 hours. This first account is an **Admin**. Admins create invitations from **Account → Team** and choose whether the invitee joins as Admin or Editor; there is no public registration or email delivery service. Share invitation links privately.

Changing the public hostname does not change accounts or passwords. Session cookies belong to the hostname, so users sign in again on the new origin; completed invitations must not be reused. The entry HTML is served with `Cache-Control: no-store`. The login gate compares the editor’s project schema with the server’s schema before opening the workspace; on a mismatch, reload the page or restart a stale local server, without downgrading or rewriting projects.

There is no self-service email reset. A lost password is recovered with a single-use reset link that expires after 24 hours. An admin creates it from **Account → Team → Reset password** (`POST /api/users/:id/password-reset`, returning `{email, expiresAt, url}`) and shares it privately. Whoever opens it enters the account email and a new password of 12–128 characters (`POST /api/auth/reset` with `{email, password, token}`); this signs the account out everywhere and signs in the current browser. Creating a link keeps the current password and sessions valid; a newer link replaces the previous one. Both steps appear in **Account → Activity**.

When no admin can sign in, the operator issues the link on the server with the same `FLOC_DATA_DIR`, `PORT` and `FLOC_PUBLIC_ORIGIN` as the editor:

```sh
npm run password-reset -- you@example.com
```

On Fly, run it inside the machine as the unprivileged app user, so SQLite files keep their owner:

```sh
fly ssh console -C "gosu node npm run --prefix /app password-reset -- you@example.com"
```

There are two roles. **Admins** invite people, change roles, create password reset links, remove accounts (which signs them out everywhere), run storage cleanup (`POST /api/storage/cleanup`), curate the workspace font library in **Account → Fonts** and read **Account → Activity**. **Editors** do everything else: open, edit, save and restore shared compositions, upload media, use workspace fonts, export and pair their own renderer. The server enforces these roles (403 for editors on `/api/auth/invitations`, `/api/users`, `/api/users/:id`, `/api/users/:id/password-reset`, `/api/storage/cleanup`, `/api/audit`, `POST /api/fonts` and `PATCH`/`DELETE /api/fonts/:id`); the editor only hides controls editors cannot use. A workspace always keeps at least one admin: demoting or removing the last admin is refused with 409. Workspaces created before roles make their earliest account Admin and every other account Editor. Admin API: `GET /api/users` (id, email, role, createdAt, lastSeen), `PATCH /api/users/:id` with `{role}`, `DELETE /api/users/:id`, `POST /api/users/:id/password-reset`, `POST /api/auth/invitations` with `{email, role}`.

The activity log records invitations created and accepted, role changes, password reset links created and used, removed accounts, successful sign-ins, compositions created, renamed, deleted or restored to a version, workspace fonts uploaded, renamed or deleted, storage cleanups and duplicate-media merges with their counts, exports queued, cancelled, finished or failed (with format and resolution; outcomes are attributed to whoever queued the export) and renderer pairings. It keeps the newest 10,000 events. `GET /api/audit?before=<id>&limit=<1–200>` returns `{entries, next}` newest first; pass `next` as `before` for the following page.

Passwords are stored as salted scrypt hashes. Sessions use random, hashed server-side tokens and HttpOnly, SameSite cookies, with Secure cookies on HTTPS. Sessions expire after seven days; signing out revokes the current session. API data, uploaded media, workspace fonts and MP4 downloads require authentication. Renderer devices keep their separate bearer credentials, restricted to worker operations, asset and workspace font reads and export status. Use HTTPS for public hosting. Accounts, sessions and renderer registrations live in the workspace database; back it up with the workspace backup below.

Everyone who signs in has access to the whole shared library. Opening or reloading Motion starts a new **Untitled** document with a white Background, no selected layer and the playhead at zero; the remembered composition is not automatically opened. Saved compositions stay in **Compositions**. When a tab is reloaded, its previously autosaved, unlinked draft is preserved there before a new draft ID replaces its stored reference. Untouched new documents do not add empty library entries. If preservation fails, the old reference is retained and **Retry opening** retries without duplicate snapshots; editing stays disabled until opening succeeds. Renewing an expired session does not reset the document already open. **Reload latest project** remains an explicit reload of the current document, not a new file. Saved compositions use their own `updatedAt` revision; drafts use independent IDs and revisions. Conflicting saves are rejected instead of overwriting changes. The previous `project.json` is preserved and migrated into the library once; it is no longer the active global draft. Existing media paths remain valid.

Workspace state (accounts and roles, sessions, invitations, drafts, compositions, version history, renderer registrations, the workspace font library and the activity log) is stored in `FLOC_DATA_DIR/floc.db`, a SQLite database opened through Node's built-in `node:sqlite` with WAL, foreign keys and a busy timeout; it is created with mode 0600 and migrated in order at startup. The first start after upgrading imports the earlier JSON files (`access/`, `drafts/`, `templates/`, `renderers/`) in one transaction and records completion, so restarts never import twice. The JSON files are left untouched as a legacy backup and are no longer read or updated; render jobs stay as files under `renders/` so renderers never load database code.

The Dockerfile builds the frontend and scene bundle, installs only production Node dependencies, and includes Chromium and FFmpeg. `fly.toml` selects this image, port 8080 and the public origin. Local project data is excluded from the image. These files do not deploy the app by themselves.

`FLOC_DATA_DIR` selects writable storage for the saved project, uploads and exports (default `.data/`). Fly mounts the `floc_data` volume at `/data` and stores application data in `/data/floc-motion`. The container initializes ownership of this directory, then runs Node without root privileges. Hosting uses one machine: data persists across deployments, but there is no machine redundancy or simultaneous collaborative editing. Separate machines do not share projects or uploads; do not scale this SQLite-backed editor horizontally. The volume must exist before deployment.
### Workspace backup and recovery

Fly keeps automatic daily snapshots of the encrypted `floc_data` volume for five days. These snapshots are the first recovery layer, but they remain in the same Fly account. Keep periodic portable copies outside Fly as a second layer.

Create a portable backup directory, preferably from a write-idle workspace. The database is copied through SQLite's online backup, so it is consistent even while the editor runs; uploads and render files are copied as files:

```bash
npm run workspace:backup -- /path/to/floc-backup /path/to/workspace
npm run workspace:verify -- /path/to/floc-backup
```

The workspace argument defaults to `FLOC_DATA_DIR`, then `.data`. The backup contains a self-contained snapshot of `floc.db` (accounts, sessions, drafts, compositions with their version history, renderer registrations and the activity log), uploaded assets, the legacy JSON directories and `project.json` when present, and render `job.json`, `render-input.json`, and `render.log` files. It deliberately excludes generated engine files, render MP4s, prepared assets, frame directories, diagnostics, and `.tmp`/`.upload` files. `manifest.json` (format version 2, with a `database` entry naming the snapshot and its schema version) lists every included file in sorted order with its byte count and SHA-256 digest. Version 1 backups made before SQLite still restore; the server imports their JSON on first start. Treat the backup as sensitive because it contains account and device credential hashes.

Restore only while the application is stopped, into a missing or empty directory:

```bash
npm run workspace:restore -- /path/to/floc-backup /path/to/restored-workspace
```

Restore verifies the complete manifest, allowed paths, payload inventory, sizes, and hashes before writing, and runs SQLite's integrity check on the database snapshot both in the backup and in the staged copy. It refuses symbolic links, traversal paths, extra or missing payload files, corrupt files, and non-empty targets. There is no force or overwrite mode.

For Fly, create and verify the copy in ephemeral `/tmp` storage, download it before restarting normal writes, and then remove the temporary copy. Do not place the portable backup under `/data/floc-motion`, because that consumes the same volume and is not an independent copy. Fly volume restore remains a separate operator procedure: create a new volume from a selected snapshot, attach it to a stopped replacement machine, verify the workspace, and only then switch service traffic. Never restore over the attached live volume.
## Motion library previews

The motion library includes real six-second sample clips for each of the 13 base templates and all 17 catalog presets, rendered through the shared scene/export engine with local studio images. Clips play only while visible; the library provides a pause control and respects reduced-motion preferences. Base-template samples illustrate standard settings; preset samples use their actual supported recipe values, including orientation, card count and loop timing. The six-second excerpt repeats without changing the preset duration. These samples use studio images, not the current composition. Documentary reference sheets remain available in preset details. Presets with no visible cards in the sampled interval display an explicit notice rather than substituting a different configuration.

Regenerate the committed 480×270 MP4 clips and JPEG posters with `npm run previews:templates` or `npm run previews:presets`. This uses local Chrome and FFmpeg only; no project is saved or published.

## Implemented

- Circular, horizontal, flip, zoom-through, stack-shuffle, sweep-reveal and window-push carousel templates, plus the six original families below.
- One ordered catalog of ten effects for every visual layer: Noise, Blur, Monochrome, Duotone, Chromatic split, Liquid wave, Optical Warp, Halftone, Dithering and Fluted glass. A carousel’s Edge stretch is a motion property, not a separate effect.
- Shared ordered image collection (up to 48 images); upload, reorder and remove. Each carousel can also hold up to 48 cards of its own.
- Independently editable text layers; local image logo; layer visibility, stacking and timing; undo/redo (up to 200 edits or ~8 MB of compact diffs per composition). Each composition or draft keeps its own undo stack while you switch between them in a session, as long as it reopens unchanged; importing a project starts a new stack.
- Solid-color, image or silent video background, with cover/contain and video offset/loop controls.
- Music upload, source offset, volume, looping and fade in/out.
- Canvas formats: 1:1 (1080×1080), 9:16 (1080×1920), 16:9 (1920×1080), 3:4 (1080×1440) and 4:3 (1440×1080); 1–300 seconds, 24/30/60 fps; up to 50 layers. Limits live in `src/project-limits.js`; effect-heavy compositions cost more than plain layers.
- Play, pause and seek; the same deterministic Three.js renderer drives preview and HyperFrames capture.
- Local MP4 export using HyperFrames, followed by an FFmpeg music mix and FFprobe verification.
- Autosave, project JSON import/download, optimistic revision checks.
- Native WebMCP tool registration and visible capability status.
- A local catalog of 17 reconstructed carousel recipes (curated from 108 observed references to remove duplicates, near-duplicates, entries that repeat their base template, and cropped, cluttered or purposeless vertical variations), with visual contact sheets and a validated adapter into the canonical FLOC carousel model.

## Files and privacy

### 3D model imports

**Add layer → 3D model**, **New composition → Add files**, and a model's **Replace file** accept GLB and OBJ. Select an OBJ together with its declared `.mtl` files and local PNG, JPEG, WebP or AVIF textures. Each OBJ bundle becomes one 3D layer; referenced companions do not become extra media layers. Replacement requires exactly one model.

OBJ is converted in the browser into an embedded binary GLB before uploading. Geometry, normals, UVs, vertex colors and material groups are retained; MTL colors, opacity and supported texture channels are adapted to glTF's PBR materials. The layer keeps the original OBJ display name. Preview and export use the same shared model renderer. GLB uploads retain their original bytes, materials and animations; embedded clip playback is independent of automatic pose motion.

Each input file, an OBJ's referenced bundle and the converted GLB must fit within 75 MB. Textures are limited to 4096 px per edge and 20 megapixels. Missing, ambiguous or remote resources, invalid geometry and unsupported MTL channels/options fail explicitly instead of silently losing materials. Relative texture paths resolve only against the files selected by the user, never the filesystem or network. GLB requirements are unchanged: GLB 2.0 with embedded buffers/textures; Draco, Meshopt and KTX2/Basis compression are not supported.

#### Material, lighting and movement

Models use the same **Design / Motion** inspector tabs as every layer. Design keeps authored framing, materials and lights; Motion contains automatic movement, shared rhythm/character controls and embedded clip playback. **Material** presets are grouped by family: **Basics** (Original, Matte, Gloss plastic, Ceramic, Candy lacquer, Rubber), **Metals** (Mirror chrome, Satin steel, Polished gold, Rose gold, Copper, Brushed aluminium, Brushed gold, Gunmetal; colors follow each metal's measured reflectance), **Iridescent** (Iridescent metal, Holographic foil, Anodized titanium, Oil slick, Pearl), **Fabric** (Velvet) and three glass families. Below the preset, three independent choices describe the surface. **Base surface** sets where it comes from: **Imported** preserves the imported appearance; **Tinted** multiplies the imported base color while keeping maps and vertex colors; **Custom** creates an opaque material with the chosen color instead of inheriting baked maps, vertex colors or source-material transparency; the layer's own opacity still applies. Roughness, metalness, clearcoat, iridescence and emissive controls operate on the custom surface, and **Surface details** add clearcoat roughness, **Brushed** anisotropy with a brush direction, **Sheen** (color and roughness) for fabric glow, and the iridescent thin film's index and thinnest/thickest thickness in nanometres, which set its hues. With a thickness range, a generated, smooth tiling thickness field makes the hues flow over the surface; with equal bounds the film has one thickness. Brushing and the flowing film need model UV coordinates; on meshes without them, brushing is ignored and the film uses its thickest value. These details default to the values the renderer already used (one 400 nm film, no brushing or sheen), so earlier projects render unchanged without a schema step. **Look** sets how the surface is lit: **Physical** (lit PBR with reflections), banded **Toon** or unlit triangle **Wireframe**, separate from the layer's post effects. Glass and **Edge glow** (a view-angle-dependent rim in its own color and power, off at 0) exist only on the Physical look, and edge glow only without glass; choosing Toon or Wireframe turns both off. Unlit source materials stay unlit on Imported and Tinted bases with the Physical look and no edge glow; a custom base, Toon, edge glow or glass adapts them.

**Glass** offers three types, each with its own preset family. **See-through** (Clear, Frosted, Tinted, Smoked and Soap bubble) transmits the background without bending it: its tinted **Glass body** covers a share of the background, the **refractive index** makes the edges more reflective and opaque, and reflections are added on top. Frosted glass softens its reflections and whitens its body. **Environment** (Prism, Diamond and Frosted crystal) bends view rays into and out of the model and samples its own reflection environment, one index per color for **Dispersion**; it is opaque, with the most contrast under Dark stage, Sunset or Neon. Without an environment it refracts a neutral horizon. Both use the same supplied-time material in preview and export.

For refraction of the composition itself, choose **Glass → Refractive**, or **Clear refraction**, **Frosted refraction** or **Prismatic refraction**. Spatial glass samples the shared-camera background and depth-tests against other geometry; Flat glass retains the earlier lower-layer-stack semantics. Text, media, carousels, backgrounds, models and their effects participate. Roughness blurs the captured image, **Dispersion** separates color channels, **Refractive index** controls bending and **Thickness** is relative to normalized model size. Imported and Tinted bases retain imported base/normal maps and source opacity; Custom uses the chosen opaque surface. Captured colors are not exposed or tone-mapped twice, and are premultiplied before filtering to avoid dark edges against transparency.

**Refraction samples** offers 4, 8 or 16 samples; **Refraction resolution** caps the captured image's longest edge at 256, 512, 1024 or 2048 px (defaults: 8 samples, 1024 px). Higher quality costs more. The shared scene renders coverage and beauty passes for each refractive model, including partial layer opacity and transparent output. This is screen-space refraction, not ray-traced volume transport; content outside the composition is transparent. The material adapts the MIT-licensed Drei transmission shader without React, remote resources or a second renderer context.

With **Dispersion = 0**, each refraction sample reads RGBA once instead of sampling each color channel separately. Nonzero dispersion keeps spectral RGB sampling. The renderer caches a program for each mode and sample count: crossing zero may compile its program on first use, then reuses it. This reduces material sampling cost without changing quality controls or promising a matching whole-editor FPS gain.

Design shows **Transform** (position, depth, size and Orientation), **Object framing**, **Material** and **Lighting**; Material starts open and every section summarizes its state when folded. Controls that do not apply to the current base, look or glass are hidden: custom surface values appear with the Custom base, Refractive glass exposes roughness and refraction on every base, environment intensity only with an environment, and embedded clip playback only with a clip. Material presets change only the surface (base, color, PBR values, emissive, look, glass and edge glow); they keep lights and the environment. A model on the Imported base with the Physical look, no glass and no edge glow shows the **Original** preset; anything else on that base is **Custom**. When a metallic or see-through/environment glass surface has no environment, the inspector suggests a lighting preset with one.

Projects saved before schema v15 had one **Material mode** (Original, Tint, Replace) and one **Surface shader** list (Standard, Toon, Fresnel, Wireframe, Glass, Studio glass, Refractive glass). They migrate to Imported/Tinted/Custom, the matching look, and See-through, Environment or Refractive glass; Fresnel becomes the Physical look with its edge glow intensity, and every other surface gets edge glow 0. A Fresnel surface saved with intensity 0 on an unlit imported material now stays unlit instead of being adapted to lit PBR.

**Lighting** presets change only the environment, tone mapping and light rig: **Studio** (bright softbox environment, Neutral tone mapping and a soft key/fill/rim rig; the default for new models), **Dark stage** (hard softboxes on black), **Sunset** (sky with a low sun and warm/cool lights), **Neon** (magenta and cyan tubes), **Classic** (the earlier hemisphere and key light without environment or tone mapping) and **Classic reflections** (Classic with the earlier room environment). Reflection environments (None, Classic room, Studio softboxes, Dark stage, Sunset sky, Neon tubes) are generated locally from small scenes; no HDR download or remote resource is used. **Tone mapping** None keeps the classic output, which clips bright light to flat white; **Neutral** and the softer, less saturated **AgX** roll highlights off. **Exposure** (25–400%) scales the light before tone mapping. Ambient, key, fill and rim lights have intensity and color, and the rig rotates as a whole. Schema v13 adds tone mapping, exposure and light colors, migrating existing models to None, 100% and white so they keep their look. These are environment reflections, not ray-traced reflections between objects; Toon and Wireframe do not reflect the environment. Per-instance materials isolate edits even when layers share decoded geometry/textures, and each model's reflection target is released with its scene.

**Object framing** controls the model's normalized frame, not the composition camera. **Fit motion**, the default for new models, keeps authored/keyframed rotation, automatic motion and the selected embedded clip inside that frame at 100% zoom. **Fixed**, retained for v10 and older models, allows motion beyond it. Zoom (25–400%) changes model scale. Flat presentations also retain their independent Perspective (15–75°); Spatial models use **Composition → Output camera** for perspective. Schema v11 introduced model framing; v14 preserves it while adding the common camera.

On the canvas, a model is selected, snapped, aligned and resized by its projected silhouette. Shared-scene picking uses rendered coverage and depth, so empty pixels reach visible geometry behind. Spatial models and carousel cards draw directly into the common depth buffer; Flat presentations are captured at the active resolution. The composition shares one WebGL renderer rather than creating a context per model; a lost context keeps the last preview frame, redraws on restore and fails an active export.

**Automatic motion** adds Spin, Rock, Float or Pulse to the authored pose. Choose X/Y/Z, or Auto to retain the original axes: Spin Y, Rock Z, Float Y and uniform Pulse. **Axis space** decides what those axes are. **Screen**, the default, turns, moves and scales about the view (X horizontal, Y vertical, Z toward you) whatever the model's orientation; **Object** uses the model's own posed axes, so a tilted model spins about its tilted axis. Projects from schema v11 and earlier keep **Legacy**, which adds motion to the orientation angles (X behaves like Screen, Z like Object, Y in between); it is offered only while a model uses it. Schema v12 adds the axis space. On the canvas, Shift-drag turns a model about the screen's vertical and horizontal axes and the rotation handle or Alt-arrows roll it about the view direction, whatever its current pose; the Orientation fields still edit the stored X/Y/Z angles. The Motion tab shares the carousel's **Rhythm** and **Character** components, clock and easing library: Original, Linear, Ease in-out, Ease in, Ease out, Back, Bounce and Spring, with the same strength controls and progress graph. Back/Spring overshoot remains visible rather than clamped.

**Continuous** uses cycle duration and a speed multiplier (100% = 1). **Actions** uses explicit action/pause durations; Spin advances by `360 / steps per turn` degrees per action, while Rock/Float/Pulse complete one oscillation then hold rest. Forward/Reverse/Paused applies to both modes. Actions ignores speed magnitude, as carousel actions do; entering Actions in the UI preserves direction and normalizes nonzero rate to its sign. Times are stored in seconds and displayed in milliseconds. Amplitude affects Rock/Float/Pulse, not a complete Spin turn. Every sample overwrites XYZ rotation/translation/scale, so axis changes and reverse seeks cannot accumulate stale transforms.

**Reset motion** keeps the selected movement, axis space, authored pose, materials, lights and embedded clip controls, restoring only neutral timing, axis, amplitude and rate. Material and lighting presets likewise preserve movement settings.

The **Embedded clip** selector lists the animations decoded by the preview, or None. Its speed, source offset and loop are independent of automatic motion, including Actions pauses. Clip speed zero holds the source-offset pose. A missing positive clip index reports an error instead of silently playing another animation; None remains available to recover even before a clip list is available. Replacing the model source resets clip selection to the first clip while preserving other styling. Static models remain valid. Schema v9 adds frozen legacy-preserving defaults to v8 models; v10 adds neutral continuous/native/auto-axis timing to v9 models without changing their previous movement. Material/light/motion/clip settings are shared across linked formats while authored framing remains format-local. Edits use normal validation, save and undo.

### Studio typography

Text layers support Druk Wide Heavy (900), Geist Regular/Bold (400/700), and Geist Mono Medium/Bold (500/700). Geist 600/800 remain available for existing compositions. The same bundled WOFF2 registry drives the font selector, canvas measurements, preview and self-contained MP4 jobs; fonts are not fetched from a CDN at runtime. Existing text without a font ID keeps Geist and its original weight. New demo headlines use Druk Wide, with Geist Mono for the signature; saved projects are not restyled automatically.

Geist Mono assets come from `@fontsource/geist-mono@5.3.0`; Geist assets come from the existing Fontsource package. Their OFL licenses are included in `public/fonts/`. Druk Wide was supplied by the studio; its commercial web/embedding permissions must be confirmed before publishing it.

#### Workspace fonts

Admins add licensed fonts in **Account → Fonts**: WOFF2, WOFF, OTF or TTF up to 10 MB, one file per weight and style. The server checks the magic bytes (`wOF2`, `wOFF`, `OTTO`, `0x00010000`/`true`) against the extension, rejects font collections, damaged files and exact duplicates (SHA-256), and reads the family, subfamily, `OS/2` weight and italic flag from the font tables (WOFF2 table data is Brotli-decompressed with `node:zlib`). A typed family name replaces the embedded one; family, weight (100–900) and style can be renamed later. Files are stored as `FLOC_DATA_DIR/fonts/<id>.<ext>` and included in workspace backups. API: `GET /api/fonts` (any signed-in user), `POST /api/fonts?name=<file>[&family=&weight=&style=]` with the raw file, `PATCH /api/fonts/:id` with `{family, weight, style}`, `DELETE /api/fonts/:id`; the files are served from `/fonts/workspace/<id>.<ext>` to signed-in users and paired renderers with private, no-store caching.

Every editor sees the library in the text **Font** selector, under **Workspace** after the studio fonts. A text layer stores the exact face as `font: "workspace:<id>"` with its weight. Preview and export declare each face under the alias `floc-workspace-<id>` together with the other weights of its family and style, so CSS font matching uses the nearest available weight, and the editor waits for the faces before the first frame. Validation accepts any well-formed workspace ID (it has no font library); a face that is not in the library renders in Geist and the inspector shows a missing-font warning. A face cannot be deleted while a composition, one of its retained versions or a draft names it; the 409 lists them. Exports copy the referenced faces into the job folder (`fonts/`) with relative `@font-face` rules; the face list travels with renderer jobs and renderers download the files with their renderer credential (a face deleted meanwhile falls back to Geist). Renderers installed before this release must be updated.

Uploaded assets and saved projects live in `.data/` (git-ignored). Server-local and legacy shared-worker exports also live there. A personal renderer instead saves each verified export (`.mp4`, `.mov` or PNG-sequence `.zip`) to `~/Movies/FLOC Motion` on macOS or `~/Videos/FLOC Motion` on Windows; the file is never uploaded to Fly. Existing filenames are never overwritten: collisions create ` (2)`, ` (3)`, and later numbered copies. Rendering copies only selected resources into a self-contained local job directory. No remote assets are accepted in imported projects or agent edits. HyperFrames telemetry is disabled for app renders. Uploaded SVG/code is not accepted; bundled original examples and the known official FLOC SVG are explicitly allowed.

Project JSON references local resource paths; it is **not** a portable archive. Keep `.data/assets/` when moving the installation. Deleting a project does not immediately delete media; only reference-aware cleanup can remove assets after the retention period.

Workspace media is capped at 1.5 GB. `GET /api/storage` reports total, referenced, orphaned and cleanup-eligible bytes. Orphans are retained for seven days. `POST /api/storage/cleanup` (admins only) performs a dry run by default; send `{"confirm":true}` to remove only eligible unreferenced assets. Uploads that would exceed the quota first run the same safe cleanup, then return HTTP 507 if referenced/recent media still leaves insufficient space. References come from an index the database maintains for drafts, compositions and every retained version (so restoring a version never loses its media), plus render job files and the legacy `project.json`. Cleanup aborts if one of those files cannot be read. The media library lists unreferenced uploads too; keeping a file there does not protect it from cleanup, using it in a saved composition does.

Media is stored once per content. An upload whose bytes match a stored file of the same format (JPG and JPEG count as one) stores nothing new: `POST /api/assets` returns the existing asset, which moves to the top of the library and restarts its seven-day grace; the library keeps the name of its first upload. At startup the server merges identical files already in the workspace (uploaded before deduplication, or restored from a backup): it keeps one copy (one a render job still names, otherwise the oldest), relinks every draft, composition and retained version to it, and deletes the copies nothing names any more; the merge is recorded in Activity. Render job files are never rewritten, so a copy they name stays on disk, hidden from the library, until the job is gone and the next startup removes it. Merged copies remain aliases of the kept one: their `/assets/...` URLs keep serving it, and a composition, draft or export sent from an editor opened before the merge is relinked on the server.

## Agent control / WebMCP

This implements the current **`document.modelContext.registerTool`** API, using AbortSignal-based cleanup. Tool execution uses the same runtime validation and autosave as human edits. See the [Chrome imperative API](https://developer.chrome.com/docs/ai/webmcp/imperative-api) and [WebMCP specification](https://webmachinelearning.github.io/webmcp/).

WebMCP is experimental and requires a compatible browser **and** agent. The Agent tools dialog reports actual availability; an unsupported browser is not presented as connected and no browser flags are changed. Registration is feature-detected, with no fake polyfill.

Tools: `floc_get_project`, `floc_list_effects`, `floc_list_catalog`, `floc_get_preset`, `floc_apply_preset`, `floc_set_carousel`, `floc_update_layer`, `floc_add_text`, `floc_set_output`, `floc_seek_preview`, `floc_request_export`, `floc_get_export_status`.

The bundled catalog is a local reconstructed recipe dataset. `floc_apply_preset` maps only supported fields into the canonical project schema and reports the fields that still need native FLOC implementations. The raw catalog is available at `/catalog/presets.json`; the editor shows its visual contact sheets in the carousel inspector.

`floc_request_export` only opens the confirmation dialog. **A person must click Render MP4.** Agents cannot publish, run shell commands, import arbitrary shader code or delete resources through these tools.

Example request: “Switch to the arc template, use monochrome at 70%, add a title at the top, and show me the frame at 3 seconds.”

A local HTTP API is also available: `GET /api/catalog` (templates, catalog metadata and the raw catalog URL), `GET /api/templates`, `GET /api/templates/:id`, `PUT /api/templates/:id` with `{name, project, updatedAt}`, `GET /api/templates/:id/versions` (version metadata, newest first), `GET /api/templates/:id/versions/:n` (one version with its project), `POST /api/templates/:id/versions/:n/restore` with `{updatedAt}`, `GET/PUT /api/drafts/:id` with `{project, revision}` for draft writes, `GET /api/assets` (the media library: `{assets: [{id, src, name, bytes, createdAt, used}]}`, newest first), `POST /api/assets?name=...` (raw file body), `POST /api/exports` with `{project, settings}` (optional `settings`: `quality` draft/standard/high, `resolution` 1080p/2160p, `format` mp4/mov/png, `transparent` for mov/png), `GET /api/exports` (unfinished exports visible to this browser in the order they will run, waiting ones with their queue `position`, then the 20 most recent finished ones), `GET /api/exports/:id`, and `POST /api/exports/:id/cancel`. Exports end as `done`, `failed` or `cancelled`; exports still running or waiting when the editor restarts are marked `failed` at startup. REST edits take effect in an already-open editor after reload; WebMCP actions update the live editor directly. Browser mutations require a same-origin request and a valid session cookie; authentication is enforced by the server.

`POST /api/drafts/:id/archive` preserves the latest persisted draft as an independent composition and returns `{composition}` (or `null` when the draft does not exist). It leaves the source draft and its revision unchanged. Each draft/revision pair is archived once, including after retries or a server restart; deleting that archive does not cause a retry to recreate it. The snapshot, its initial version, activity entry and preservation marker commit in one transaction. Like composition creation, this endpoint requires a signed-in user and a same-origin request.

## Add a carousel or effect

1. Add a carousel to `TEMPLATES` in `src/project.js`, or an effect and its defaults to `EFFECTS` / `DEFAULT_FILTERS` in `src/effects.js`.
2. Derive every visual value solely from supplied time. Shared layer effects are built in `createEffects`; carousel-only geometry belongs in `src/scene.js`. A parameter that needs new decoders, meshes or DOM nodes must be listed in `STRUCTURAL` in `src/scene-update.js`.
3. Add controls to `src/editor/components/EffectControls.jsx` and validate settings through `validateEffects`.
4. Run tests and build; verify seeked frames and a real export. WebMCP and catalog responses derive from the installed registries.

Adding implementations is a source-code change, not runtime execution of pasted code.

## Prototype boundaries

No simultaneous collaborative editing, cloud rendering, arbitrary plugins or 4K/GIF/WebM output. Browser preview depends on local codec/WebGL support. MP4 export is a local job; keep the server running. The local editor and each personal renderer render one export at a time; up to 50 more wait in a first-in, first-out queue (the shared Mac render worker still takes one). Exports follow the 300-second composition limit; frame capture may run for up to 6 seconds per 1080p-equivalent frame (never less than 20 minutes) before it is stopped, so a 5-minute 2160p60 export is not cut short. Long exports are slow rather than memory-bound: on an M2 Pro (4 workers) a 50-layer, 300-second 1080p30 composition took about 9 minutes with light effects, while effect-heavy compositions capture about 4× slower and 2160p about 4.5× slower again. This is a functional prototype, not production acceptance or a complete replica of the references.

## Original family motion engine

The engine has eight original families and 20 motion variants; the 17 catalog presets are recipes over them, not separately implemented animations. Orbit and Sliders use Circular and Horizontal; Showcase, Sphere, Spinner, Stack, Stickers and Wheel have their own evaluated transforms. Retired templates migrate on load: Depth becomes Showcase, Arc becomes Wheel with the rocking variant and Nested Rise becomes Zoom Through (schema v4); Twist becomes Flip, or a Horizontal strip for its torsion ribbon (schema v5). Stored projects are not rewritten until saved.

`src/carousel-motion.js` evaluates each card from absolute time and is consumed by the shared preview/export scene. Controls include motion variant, card count (0 uses the media count; maximum 48), aspect ratio, radius for radial families, orbit rear fade, XYZ orientation, Edge stretch and explicit loop duration. Media repeat in their original order when more cards than images are requested.

**Character** shapes each step with a progress curve: Original (the family's own motion), Linear, Ease in-out, Ease in, Ease out, Back, Bounce or Spring. Every curve starts at 0 and lands exactly on the next card; all but Linear and Ease in arrive at rest, so step mode never ends with a jolt. Its percentage sets the curve's own character rather than blending with linear: **Strength** raises the eases from linear (0 %) through cubic (50 %) to quintic (100 %); **Overshoot** sets how far Back passes the target (0–25 % of the move); **Bounciness** sets Bounce's first rebound (5–30 %), which never passes the target; **Springiness** sets Spring's first swing (5–25 %), which first reaches the target at 45–35 % of the step and then settles. The preview above the buttons draws the curve at the current percentage; Original and Linear have no percentage. Schema v6 converts the previous twelve curves on load: Smooth, Natural and Slow become Ease in-out; Glide and Vive become Ease out; Elastic becomes Spring, each with the closest strength; a curve at 0 % intensity, which showed the Original motion, becomes Original.

Catalog composition settings are applied where supported. Camera perspective, surface selection, imported material semantics, shadows and depth of field remain unimplemented. Reference contact sheets are documentation, not screenshots generated by the current engine.

Card silhouettes support a corner radius of 0–100% of half the shorter edge, with circular rounded corners or a fourth-power squircle profile. The UV-space mask follows card curvature and torsion without changing the image crop. Front/back visibility is independent; hiding both intentionally hides all cards. Legacy projects default to rectangular, double-sided cards.

**Card ratio** either crops every card to one fixed ratio (9:16, 4:5, 7:8, 1:1, 4:3, 16:9) or keeps each image's own proportions, uncropped: **Each image · same height** or **Each image · same width** (`cardFit` `height`/`width`; absent or `fixed` keeps the fixed ratio). The shared side equals that side of the fixed card at the current card size and ratio, so switching modes keeps the overall scale. Proportions come from the loaded media (video and GIF cards from their frames; ratios beyond 1:4 and 4:1 are cropped to that limit), so preview and export lay cards out identically. Horizontal, Flip slider and Showcase space neighbours by their real widths with the same edge-to-edge gap; Circular and Wheel give each card an angular share proportional to its width, and wrapped cards curve over their own width; the rocking Wheel fans by width. The other families keep their layout and only resize each card. Window Push keeps its window ratio. The fit is shared by linked formats and updates the preview in place.

## Flip slider and elastic optics

Flip slider is an additional original carousel: each step holds for 60% of its interval and eases through the next card for 40%. Transition turn (0–360°) controls the Y-axis turn independently; at a full turn the settled center and side cards face forward. **Edge stretch** is a carousel motion property: its lateral wing geometry and texture stretching follow distance from the local center, vanish at center and remain neutral at zero. Projects saved before the unified catalog migrate Elastic shader intensity to Edge stretch (schema v8).

## Shared 3D scene

New compositions use one output camera and real depth for carousel cards, models and editable text/image/logo planes. **Orthographic** is the default: X/Y placement remains a 2D design workflow, and moving a layer in depth does not change its apparent size. Graphic planes are unlit; model lighting does not tint typography or images.

1. Select a layer and open **Design → Transform**. **Depth** is a percentage of canvas height; positive values move toward the default front-facing camera. **Orientation** turns a Spatial plane or object in X/Y/Z.
2. Place a Wheel carousel around a text plane or model at Depth 0. Tilt the wheel to give its path depth: its cards can now pass both in front of and behind the center content. Layer order breaks ties for coplanar graphic planes; it does not override intersecting geometry.
3. Set depth on the canvas: with one text, logo, media, model or carousel layer selected, the **depth ruler** at the right edge of the canvas shows the other layers' pieces in the current frame (each Spatial carousel card or model as a range, each plane as a tick), Front at the top. Drag its marker to place the layer (it snaps to the stops between piece centers and to layer edges; Shift drags freely); Arrow keys step 1 (Shift 10), Page Up/Down pass one piece per step, Home/End go in front of or behind everything. The canvas hint reports how many pieces the layer is in front of and behind.
4. Select **Composition settings → Output camera** to change projection, zoom, orientation and target. These settings are saved and exported.

Schema v14 migrates existing compositions and linked-format caches to **Presentation: Flat**, keeping their original independent framing and layer-stack appearance under the default camera. Conversion is explicit: choose **Spatial** in Transform when ready to share that layer's geometry; its perspective and overlaps may change. A Flat presentation remains a plane in the common scene and can also be positioned in depth.

Layer effects remain image-space treatments. Spatial models/carousels carry their depth and picking coverage through effect packets; Below adjustments process the grouped result. The engine is split into supplied-time scene orchestration (`src/scene.js`), cameras, native capture, surfaces, render passes and the shared world (`src/scene-*.js`), used by preview and export alike. Reflection environments and lighting remain per model; this does not add mutual ray-traced reflections or scene-wide shadows.

## Positioning

Every visual layer's **Transform** section edits X/Y percentages, size where applicable, and rotation or orientation; graphic, model and carousel layers also expose Presentation and Depth. Spatial text and logos move freely on their projected depth plane; Flat text and logos keep the 6×6 anchors inside a 5% safe area. The canvas toolbar aligns visible projected bounds to the canvas or enabled safe area. Placement guides are editor-only. Every route commits validated project coordinates through `src/project.js`.

### Preview continuity

The editor retains the active animation while preparing a replacement scene. Parameter edits (effects, carousel motion, size and appearance, colors, timing, text, procedural backgrounds, and model materials, lighting, automatic motion and clip selection) update the live scene in place. Only structural edits rebuild it: adding, removing, reordering or retyping layers, changing the format, a carousel template, card count or card sources, a media, model or background source/mode, or an adjustment scope; changing a font face rebuilds when the face is not loaded yet.

The preview canvas composites empty areas and translucent layers over white, matching MP4 and other opaque exports. The dark dotted workspace stays outside the composition and is never part of its pixels. New documents include a white **Background** at the bottom of Layers: select it to edit its color, image, video or procedural pattern. It stays below new content and cannot be deleted, duplicated or reordered; it is not locked by default. Up to 49 imported media layers fit alongside it in the 50-layer limit. Older compositions retain their authored colors, transparency and background stacks without a migration; existing backgrounds keep their stacking boundaries. **Transparent background** remains an opt-in for MOV and PNG exports: it omits backgrounds without removing them from the document.

### Direct canvas editing

Click visible text, media, a model or a carousel card to select its layer and synchronize the inspector. Drag to move; Shift-drag a carousel or model to orient X/Y, and Shift+Alt-drag or the rotation handle to turn Z. Spatial movement follows the output projection; Flat text/logo movement retains grid anchors. Arrow keys nudge the selected layer, with orientation keys on the orientation controls. Escape cancels the draft; pointer release commits one undoable edit. Locked layers can be selected but not manipulated.

Wheel over the selected element to resize: font size for text, logo size, or card size for the carousel. Alt+wheel changes its depth instead (about 2% per notch, wheel up moves toward the camera; Shift+Alt ×5). A wheel burst commits one edit after 250 ms, using existing validated bounds. Ctrl+wheel is left to the browser. Outlines, guides and the rotation ring are editor-only and are never exported.

With one depth-capable layer selected and focus outside text fields and dialogs, Page Up/Down moves it 1% toward or away from the camera (Shift 10%), ⌘]/⌘[ (Ctrl on Windows/Linux) moves it past one more of the other layers' pieces in front or behind (one piece per step, measured at piece centers, so overlapping tilted cards are still passed one at a time), and ⇧⌘]/⇧⌘[ places it in front of or behind everything. Each press is one undoable edit at the playhead, keyframed like other canvas edits on choreographed layers. Steps are read from the frame on screen, so pieces of a turning carousel can differ at another time. Multi-selections, locked, hidden and out-of-range layers do not take depth edits.

### Choreography states

Text, logos, media, carousels, 3D models and effect layers support up to 32 choreography states per layer. Every state holds the pose; carousels and models also hold tilt and yaw. Saving a state also captures text typography, carousel Edge stretch, and the primary amount of the layer’s first effect of each type. Projects saved before schema v8 migrate carousel shader and finish animation fields into those effect amounts.

Click a state to seek to it; drag its timeline diamond or edit **Time (s)** to move it. Arrow keys move a diamond by one frame (Shift: ten), Home/End move within its neighbors, and Delete removes it. Each destination state picks the curve of its incoming transition from the shared easing library, also used by carousel progress curves: Linear, Ease in-out, Ease in, Ease out, Back, Bounce, Spring (each at 50 % strength), or a custom cubic bézier (`x1, y1, x2, y2`; both x values between 0 and 1) with a curve preview. Transitions saved with Smooth, Natural or Slow load as Ease in-out, Glide or Vive as Ease out, and Elastic as Spring (schema v6). Overshooting curves stay within each property's limits. States move with their layer; trimming preserves states outside the visible clip. Undo and layer locks apply to state edits. Preview and export evaluate the same values from the supplied time and apply them to the live scene without rebuilding it.

### Editable template content

Give a text, carousel, logo, media or music layer a **Template field → Field name** in the inspector to expose its content. Leave the name blank to keep that layer out of the content form. A field can be marked **Required**, and text fields can set **Maximum characters** (1–500). Each field gets a stable ID (shown in the inspector, e.g. `headline`, `headline-2` for a repeated label) that survives renames; its type follows the layer. Projects saved before typed fields (schema v2) migrate on load: each label becomes an optional field with an ID derived from it. Save the composition, then choose **Use as template** in **Compositions** to fill these fields and create an independently saved composition. **Open composition** continues to edit the original saved entry.

The header's **Content** form edits only declared fields, including content in locked layers. Required fields are marked and text with a maximum shows a character counter; **Apply** stays disabled while a required field is empty or text is too long. Position, styling, timing and choreography stay intact; configuring field names still requires an unlocked layer. Carousel uploads replace only that layer's cards. Changes remain in a private preview until applied as one undoable edit; Cancel leaves the composition unchanged.

**Batch variants** in the Content form turns the template into a table with one row per output (up to 50) and one column per field. Type values, pick media from files already used in the workspace or upload new ones, or paste CSV/TSV rows: a header row may name columns by “Name”, field label or field ID (without one, columns are the name followed by the text fields); media cells take an uploaded file name and carousel cards are separated by `|`. **Review** checks every row before anything is saved: empty required values, text over its maximum, text that does not fit the safe area (or runs past the frame) at any choreography pose in each selected linked format — laid out with the same stage markup and bounds the editor uses — missing or unsupported files, and duplicate or empty output names. Only a clean review enables **Create compositions** (each row becomes its own saved composition) and **Export all** (one export per row and selected linked format, queued with the settings chosen in **Export**). Exports still need this click; agents cannot start them.

### Linked format versions

Enable **Linked formats** under Canvas to make the current ratio the master and generate assisted adaptations. Content, assets, layer order, visibility, duration, media settings, carousel motion, choreography timing and animated effect values remain shared; each format keeps its own pose, framing and typography layout.

Correct a version with the ordinary inspector and canvas controls. **Reset from master** regenerates the active adaptation from the master's current layout. Disabling Linked formats retains the active composition and removes the other layouts. These actions are undoable. Saved compositions and project JSON retain all versions; preview, agent output switching and manual MP4 export use the active version through the same scene engine.

### Layers

The layer list shows frontmost layers first. Each row shows the layer name with its kind underneath (the text for text layers, the template for carousels) and keeps visibility and lock buttons visible; Rename, Duplicate and Delete appear when a pointer hovers the row or keyboard focus reaches it, and stay visible on touch screens. Hidden layers are dimmed. Drag a content row to reorder it; the insertion line indicates its new position. Double-click a name (or use Rename / F2) to rename it, Enter to commit and Escape to cancel. Arrow buttons and Alt+Up/Down provide keyboard ordering. The composition background has no drag grip, Duplicate or Delete action, and content cannot move underneath it. Group deletion and duplication skip backgrounds. Other layers can be duplicated above their source, with a 50-layer project limit.

With nothing selected — click empty canvas, press Escape or use **Composition settings** (the gear in the layer list heading) — the inspector edits the composition itself: **Canvas** (aspect ratio, linked formats, duration and frame rate) and **Layout** (safe margins in 0.5% steps and smart guides). A selected layer starts with a common header: its editable name and kind, visibility and lock, and **Replace** for logos, media, 3D models and soundtracks. Two tabs follow for every layer. **Design** holds what the layer looks like: its own content (Cards, Content and Typography, Background source, Material, Soundtrack volume), **Transform**, **Appearance** (opacity and the effect stack) and Template field. **Motion** holds how it changes over time: carousel Rhythm and Character, the text **Reveal**, model Automatic motion and Embedded animation, **Playback** (source offset, loop and the soundtrack fade) for video, GIF and audio, and **Entry & exit** fades; keyframes stay in the timeline. Inspector sections fold to their title and a short summary such as “Fit motion · 100%” or “Fade 450 / 250 ms”, and work as an accordion: opening one folds the others in the same tab. Until a section is chosen, the main one starts open (Content for text, Cards for carousels, Rhythm on a carousel's Motion tab, Transform for logos and media, Material and Automatic motion for models, Canvas for the composition, Arrange for a multi-selection); the section last opened (or none) is remembered per layer type and tab in that browser. Sliders are compact and neutral, and show the accent fill only while in use; help text is one short line, and controls that do not apply are hidden rather than disabled. Numeric fields accept decimals where their step needs them, with a point or a comma.

**Add layer** separates what it adds. **Import** opens the file picker for one kind: **Image or video**, **Audio** or **3D model**; **From Media** opens the media library to reuse an upload. **Create** adds a **Text**, **Carousel**, **Adjustment** or **Studio mark** layer. The background already belongs to the document; edit it from Layers instead of adding another. Replacing a layer's source or adding carousel cards offers **Upload** or **From Media**.

The **Media** tab is the workspace media library: every image, SVG, GIF, video, audio file and 3D model uploaded by anyone in the workspace, newest first, with its file name, kind and size, a check on items the open composition uses, a search field and All / Images / Video / Audio / 3D filters. Upload adds files to the library without placing them. Drag an item onto the canvas to add it as a layer centered where it is dropped (audio becomes a soundtrack), or double-click it or use its **+** button to add it at the default position. With one layer selected, an item that fits it offers a second action: **Add to cards** for a carousel, or **Use in** for a logo, media, background, soundtrack or 3D layer, replacing its source. Uploads keep their file name in the database (migration 6); earlier uploads take the name saved next to them in a composition, preferring file names, and the rest are labelled by kind. Thumbnails load as they scroll into view. A carousel's cards are listed in its **Cards** section: drag rows or use the arrows to reorder, remove them, drop images, GIFs or videos from the library on the list to append them, or **Upload cards**. The same file can appear in several cards and compositions.

Locks persist in project JSON and prevent property, timing, order and removal edits. Locked layers can still be selected, hidden/shown and unlocked. Every editor, visual-alternative and agent change is checked against the previous project, so a locked layer cannot be altered indirectly; moving unlocked layers around it remains possible. Locks are editing safeguards, not permissions: opening or importing a project, Undo/Redo, composition-wide duration changes, linked-format switching/reset (layout fields only) and the Content form (declared fields only) retain their normal behavior. Locking does not change rendering or export.

Optical Warp smoothly stretches any visual layer’s sides around a center line, preserving the center and the untouched axis. Preview and export share the same deterministic filter on text, logos, media, models, backgrounds, carousels and adjustment groups, in its authored stack order. Large movements use exact translations; adaptive maps encode only small residual offsets instead of quantizing the entire layer-sized displacement. An unchanged RGBA source is materialized once before those views so WebGL-backed layers also render correctly at 4K. No detail-softening blur is added.

### Multi-selection, alignment and command palette

⌘/Ctrl-click a layer row toggles it in the selection and Shift-click selects the listed range from the last plain or toggled row; on the canvas, Shift- or ⌘/Ctrl-click toggles a layer (dragging with those modifiers keeps their usual meaning). ⌘/Ctrl+A selects every unlocked, visible text, logo, media, 3D model and carousel layer at the playhead; Escape clears a multi-selection back to the last clicked layer after canceling any active gesture. Dragging any selected layer or pressing the arrow keys moves every unlocked member together as one undoable edit (Shift skips snapping and uses the big nudge); the shared offset stops at the first member's position limit so the arrangement keeps its shape. Delete, duplicate, lock/unlock and hide/show act on the whole selection as one edit; locked members stay put and Delete/Duplicate report them.

With two or more layers selected, the canvas toolbar and the inspector align left, horizontal centers, right, top, vertical centers or bottom to the selection's bounds, measured from the rendered boxes the placement guides use (locked members anchor the bounds without moving). With one layer selected, alignment uses the canvas, or the safe area when layout margins are on. Distribute horizontally/vertically leaves the outermost layers in place and equalizes the gaps between three or more unlocked layers.

⌘K / Ctrl+K opens the command palette: fuzzy-search adding layers, playback, Undo/Redo, export, new/save/open composition, version history, Explore styles, timeline and zoom, alignment and selection actions, and Account. Unavailable commands are listed dimmed. Arrow keys move between available commands, Enter runs one and Escape closes the palette. **Export video…** opens the usual export dialog; nothing renders without its confirmation.

### Audio timeline editing

Use **Add audio** in the timeline to import MP3, WAV, M4A or OGG at the playhead. Drag an audio item from **Media**, or an audio file from the computer, onto the timeline to add it at the drop time. Reusing a Media item references its original file rather than uploading another copy.

Audio clips show the actual source waveform, including quiet sections, loops and any silent tail. Drag the left edge to trim the source in-point and the right edge to change its duration; extending an edge recovers available source material. Moving the clip body or editing numeric **Start** changes its composition position without changing the source in-point. After source duration is available, non-looping trim and Duration edits stop at the source end. Existing imported clips are not silently shortened. Pointer and keyboard edits use the same bounds, Escape cancels a drag, locked clips cannot be edited, and each completed gesture is one Undo/Redo operation.

The inspector's **Source offset**, volume, existing shared fade and Loop controls remain available. Loop repeats the source from its in-point to the file end; trimming its left edge changes that loop's in-point. Preview and export read the same stored timing and original audio.

Waveforms are generated locally with FFmpeg, cached in `FLOC_DATA_DIR/cache/audio-waveforms`, and served through authenticated `GET /api/assets/<audio-filename>/waveform` requests as `{ duration, peaks }`. The browser downloads a small peak summary, not decoded PCM, to draw the waveform. Multiple clips reuse the summary; loading or extraction errors do not block playback or editing, and failed waveform loads offer Retry. Originals and project JSON do not contain waveform data.

### Animated carousel media

Carousel cards accept local images, GIF, MP4 and WebM (75 MB per uploaded file). Mixed media share the existing ordering and templates. Videos loop silently from the carousel layer's start; pause and timeline seeking select the corresponding decoded frame. Repeated cards share a video decoder/texture for each source instead of loading a video per mesh. High-resolution videos and many simultaneous sources can increase preview cost.

To replace one card, select the carousel, open **Design → Cards**, and use that row's **Replace card** action. Choose **Upload file** for one image, SVG, GIF, MP4 or WebM, or **From Media** to reuse an existing upload. The entry keeps its identity and position; other entries, motion, framing and timing stay unchanged. Replacement is one Undo/Redo step and is disabled on locked carousels. Older carousels borrowing the shared image collection receive their own list, leaving other carousels untouched; linked formats still share content. If the card count repeats the list, all repetitions of that entry use the replacement.

Preview redraws triggered by soundtrack metadata or graphics-context restoration wait until card media and geometry are initialized. An audio file that loads before MP4/GIF cards must not cache empty card dimensions or leave the carousel blank.

GIFs retain their original file and get a local, cached VP9 WebM derivative for seekable playback, including older saved GIF cards. Conversion uses the already-required FFmpeg and preserves frame timing and alpha. Preview and export use the same media clock. Export waits for frame decoding through the renderer's `hf-seek`/`waitUntil` contract before capturing WebGL, rather than using an independent playback clock. Unsupported codecs or unreadable media report an error; upload format alone does not guarantee codec support.

### Saved composition templates

Open **Compositions** in the header to find saved compositions and preserved drafts, preview one, and explicitly choose **Open composition**. **Save composition** saves a complete snapshot with a name and up to ten searchable tags. A selected composition has a real, on-demand engine preview; gallery covers are media references, not rendered composition thumbnails. Rename or retag a composition without changing its saved scene. Each document keeps its own Undo history while switching within the same page session.

Saved compositions persist as validated projects in the workspace database, separately from autosaved drafts. Uploaded media are referenced in the same workspace rather than duplicated; deleting a composition (and its version history) does not delete media or the current project. These are workspace-local snapshots, not portable media archives or cross-device sync.

Every save that changes a composition's project or name records a version with its author and time; changing only tags or saving identical content does not. Autosaves by the same author within 10 minutes of when the newest version started update that version in place (its displayed time becomes the latest save), so continuous editing yields about one version per 10 minutes; another author, creating, importing and restoring each start a new version. The newest 100 versions per composition are kept. With a saved composition open, **Version history** in the header lists versions (time, author email, name). **Restore** asks for confirmation, saves pending work, and records the selected state as a new current version; older versions are never rewritten. The restore respects the composition's `updatedAt` revision and is applied as one ordinary edit, so Undo returns to the previous state and autosaves it as another version.

## Mac render worker

The shared editor can delegate exports to a trusted Mac without exposing a local port. Set `FLOC_RENDER_WORKER_TOKEN` on the shared server and create `.data/render-worker/config.json` on the Mac with `{"origin":"https://floc-motion.fly.dev","token":"<same random token>"}`. Restrict that file to the current user (mode 0600). Run `node scripts/render-worker.mjs`; the worker downloads validated project media, uses the native browser GPU, renders with the pinned HyperFrames engine and uploads the verified MP4. The existing export confirmation and download button remain in place. When the Mac is offline, new exports fail immediately with an explanatory message; interrupted jobs fail after 90 seconds without a heartbeat. Only one export runs at a time. The Mac must remain awake and connected. No Runpod resources are used.

### Visual language

Background Source includes **Procedural** with 15 patterns: twelve geometric ones (Grid, Grain, Waves, Geometry, Dots, Stripes, Checkerboard, Rings, Rays, Mesh, Flow, Halftone) and three soft ones (Gradient, Aurora, Noise). A single WebGL 2 shader (`src/background-shader.js`) draws them all. One shared, hidden context renders every background on the page, including the editor tiles, and copies each frame onto the layer's canvas, so backgrounds never take a context away from carousels or models. Geometry is measured in scene units (1080 per short side) with analytic antialiasing, so exports at any resolution show the same image and slow drifts do not shimmer. Integer-only hashes give Metal, D3D11 and SwiftShader the same random values. Every pattern is calibrated to a comparable visual weight at the same intensity and a comparable amount of motion at the same speed. Base color, pattern color, scale (larger draws a larger pattern), intensity, speed, seed, **Vignette** and **Grain overlay** are editable; grain changes once per video frame, and a speed of zero freezes everything, grain included. Scale ranges from 10% to 400%; below 25%, strokes and marks thin with the square root of the scale so fine patterns stay open instead of closing into a flat tone, while 25% and above render exactly as before. Animation derives from the supplied layer time, so reverse seeking and export reproduce the same image. Projects saved before schema v7 store scale as a density; they migrate to `1 / scale` and keep their exact size. Without WebGL 2 the preview reports the missing capability and export fails rather than capture stale frames. Image and video backgrounds remain available.

**Seamless loop** makes a procedural background repeat exactly over its layer's duration, so the last frame leads straight into the first. Drifting patterns travel a whole number of cells (checkerboard steps keep squares on squares of the same color), rotations and waves complete whole cycles, and speed rounds to the nearest whole cycle, never below one. Aurora and Noise never repeat on their own, so a loop crossfades towards the state one loop earlier. Grain needs no loop: each frame is independent. **Direction** (degrees; 0° moves right, 90° up) steers Grid, Dots, Stripes, Checkerboard and Halftone; stripes turn to stay perpendicular to their motion. **Focus X/Y** places the center of Rings and Rays as a percentage of the frame. The pattern registry in `src/backgrounds.js` declares which pattern shows which control. Backgrounds saved before these settings existed receive their pattern's original direction and their seed's original center, so they keep their exact motion and framing; a new seed no longer moves the center.

Backgrounds can be animated in the timeline: open **Choreography** on the Background track and save states. A background has no pose, fades or animated opacity; its states hold the base color and, for procedural backgrounds, the pattern color, intensity, scale, speed, direction, focus, vignette and grain (plus effect amounts, as on other layers). Solid and media backgrounds animate their fill color. Speed and direction are integrated over time, so changing them in a state accelerates or turns the pattern instead of making it jump; with **Seamless loop**, the loop still closes on whole cycles. Grain freezes while the animated speed is zero. Edits in the inspector update the state at the playhead once a state holds that value, and the pattern tiles preview the values at the playhead.

**Accent color** adds a third color to procedural backgrounds. Gradient, Aurora and Noise draw it as a second, independently seeded layer of the same field: **Accent layer** (0–100 %) sets that layer's strength, so the accent holds its own regions of the frame next to the pattern color and the base. Gradient's accent ramp runs opposite to the pattern's, so the two colors sit at either end with the base between them. Where the two layers overlap the stronger one wins, so they never average into grey. Every other pattern keeps **Accent** (0–100 %), which sets how much of the pattern's ink it takes over in two-tone regions that drift with the pattern's own time; there the accent never covers the base. Both close in seamless loops. Accent 0 renders exactly as before; both values can be animated in Choreography.

Text layers include line height, letter spacing in em, alignment and directional wipe reveals with an adjustable duration. Typography is local to each linked format; reveal direction and timing remain shared. Previews, placement measurements and export use the same style values. These settings are saved in project JSON and validated for human and WebMCP edits. MP4 export still requires **Render MP4** confirmation.

### Personal renderers (Windows / Mac)

Public exports require a renderer connected to the current browser. In **Export**, download the renderer ZIP, choose **Connect this computer**, and enter the ten-minute code in the installer. Each browser has an HttpOnly connection cookie; each engine has a separate credential. The server stores credential hashes, assigns at most one active job per engine and hands out up to 50 queued exports in order as it claims them, supports concurrent engines, and restricts progress and results to the owning connection. A renderer that stops checking in for 90 seconds fails its current and queued exports. No local listening port is opened. A personal renderer saves verified MP4 files in `~/Movies/FLOC Motion` on macOS or `~/Videos/FLOC Motion` on Windows. The editor stores only completion status and the saved path; it never receives or retains the MP4 bytes. The existing shared worker protocol remains available for existing installations, and its completed exports retain the browser download.

`npm run build` includes `dist/renderer/FLOC-Motion-Renderer.zip`; `npm run build:renderer` rebuilds just the installer. The ZIP contains only engine sources, pinned dependency metadata, bundled brand/font/demo assets, installers and the `launcher.mjs` supervisor, without credentials, uploaded media or project data. Installers download a SHA-256-verified private Node 24 runtime, install dependencies with the lockfile, provision a dedicated Chrome Headless Shell through HyperFrames, check its version response and native hardware WebGL, check FFmpeg/FFprobe, and enable per-user startup. This avoids depending on the user's everyday Chrome installation; `HYPERFRAMES_BROWSER_PATH` remains an explicit override. Windows x64 requires Windows 10/11 with WinGet; macOS uses Homebrew to install missing FFmpeg.

The build also publishes the engine alone for automatic updates: `dist/renderer/engine/<version>.zip` (`package.json`, `package-lock.json`, `src/`, `server/`, `scripts/`, `public/`; no launcher, installers, dependencies or runtime) and `dist/renderer/engine/manifest.json` (`version`, `file`, `sha256`, `size` and the `node` version both installers pin, which must match). The packaged engine's fingerprint must equal the editor's or the build fails; the manifest is written last and older packages are removed. The editor serves both publicly at `/renderer/engine/manifest.json` and `/renderer/engine/<version>.zip` with `Cache-Control: no-store`; any other path under `/renderer/engine/` is a 404.

The Windows installer replaces its private runtime after SHA-256 verification, without merging files from a previous npm version, and invokes `runtime/node.exe runtime/node_modules/npm/bin/npm-cli.js` directly. The npm.cmd launcher is not used because it can redirect to the user’s global npm. Dependency failures include the private Node/npm versions and output in `installation-dependencies.log`; `.data` and the user’s global Node/npm installation remain untouched.

The Mac installer also extracts the verified runtime before replacing its previous runtime in full and calls the bundled npm CLI through the private Node binary. Extracting over an existing runtime is unsafe: stale nested dependencies can shadow the updated npm dependencies (for example, minipass 3 beneath minipass-flush requiring minipass 7), causing `Class extends value undefined`. This replacement preserves `.data` and does not modify global Node/npm installations.

Renderer compatibility fingerprints follow the local JavaScript and JSON import graph of `src/render-entry.js` and `scripts/render-worker.mjs`, including literal dynamic imports, instead of every file under `src`. Editor-only controls, batch editing and visual-alternative helpers no longer force a renderer update unless they become runtime dependencies. Scene, shader, project-validation, export and worker changes still invalidate compatibility; unresolved runtime imports fail rather than reporting a compatible renderer. Dependency versions remain conservatively pinned by the whole `package-lock.json`. The editor and extracted renderer package calculate the same fingerprint regardless of installation path.

Renderers installed with the updater check in with `updater: 1` and their engine state (`ready`, `updating` or `failed` with a message). When their fingerprint differs from the editor's, or after **Update now** in **Export** (`POST /api/renderers/update`), the claim answers `{ update: { version, manifest, requested } }` instead of an export; the renderer updates once idle and keeps its connection. Exports queued meanwhile wait (**Waiting for your renderer to update**); a failed update fails them and blocks new ones with its reason until **Update now** or a reinstall succeeds. `GET /api/render-worker/identity` returns the engine credential's `{ id, name }` without checking the renderer in, so reinstalling can reuse the connection; it also ends a pending **Reconnect** code for that renderer, which would otherwise hold its exports until the code expired. Setup retries that check three times, five seconds apart, on network errors or 5xx responses, then stops without changing the saved connection. Renderers installed before the updater still report **Update your renderer to match the editor** and need this installer once. Use the product installer rather than patching its files so the runtime, browser check, credential, and LaunchAgent stay consistent. The installer is unsigned; Windows runtime compatibility needs an actual Windows test, not just a successful build. For local isolated checks, `node scripts/renderer-setup.mjs --origin http://127.0.0.1:<port> --code <code> --no-autostart` connects without modifying startup settings. `--check` only verifies prerequisites and GPU access.

[`docs/renderer-auto-update.md`](docs/renderer-auto-update.md) explains the update flow, Export states, installed layout, integrity checks and limits for the team.

For an existing Mac renderer whose system Chrome times out during `--version`, run `Repair-Mac.command` on that Mac. It prepares a dedicated rendering browser, verifies its version response, updates only the browser path in the existing configuration and restarts the renderer. Credentials and engine files are preserved, so this repair does not require a new connection code or an editor deployment. Wait for **Ready** before confirming **Render MP4** again.

### Visual alternatives

**Explore styles** opens three installed creative directions: Editorial, Bold and Experimental. Switch between their real previews and **Original** at the same playhead time, then choose **Apply alternative**. Comparison stays private; applying a proposal is one undoable edit through the usual autosave. Content, local media, layer timing, locks and inactive linked-format corrections are preserved.

A connected native WebMCP agent can submit 2–3 custom directions with **floc_propose_alternatives**. Read **floc_get_project** first and pass that snapshot as `base`, with each alternative's name and per-layer visual patches. Proposals use installed styles and the canonical validator; they cannot upload code, replace content or start a render. The app rejects stale proposals and changes made while another comparison is open. A person chooses which proposal to apply.

Numeric controls accept whole numbers by typing their value and pressing Enter or leaving the field; Escape restores the saved value. Fractional scales use percentages, timing uses milliseconds, and text tracking uses thousandths of an em. Preview and saved projects retain their original precision until an edit is confirmed. Nudge amount in the canvas toolbar sets Small nudge (arrow keys) and Big nudge (Shift + arrow keys), in composition pixels; preferences are saved in this browser. Alt + arrows or a focused rotation handle still adjusts rotation.
